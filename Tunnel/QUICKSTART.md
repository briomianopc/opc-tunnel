# OPC Tunnel GUI - 快速开始指南

## 5 分钟快速上手

### 前置要求

- Windows 10/11 或 Linux 或 macOS
- .NET 8.0 Runtime（运行时）或 SDK（开发）
- ech-core.exe（已包含在构建输出中）

### 第一步：获取程序

#### 方式 1: 使用预构建版本（推荐）
```bash
# 下载发布版本
# 解压到任意目录
# 进入 OpcTunnelGUI 目录
```

#### 方式 2: 从源码构建
```bash
# Windows
cd Tunnel
build.bat

# Linux/macOS
cd Tunnel
chmod +x build.sh
./build.sh
```

### 第二步：启动程序

#### Windows
```batch
# 方式 1: 双击运行
OpcTunnelGUI.exe

# 方式 2: 命令行运行
cd Tunnel\OpcTunnelGUI\bin\Release\net8.0
OpcTunnelGUI.exe
```

#### Linux/macOS
```bash
cd Tunnel/OpcTunnelGUI/bin/Release/net8.0
./OpcTunnelGUI
```

### 第三步：配置连接

1. **填写服务器地址**
   ```
   示例: your-worker.workers.dev:443
   ```

2. **填写身份令牌**
   ```
   示例: d342d11e-d424-4583-b36e-524ab1f0afa4
   ```

3. **（可选）修改监听地址**
   ```
   默认: 127.0.0.1:30000
   ```

4. **选择传输模式**
   - WebSocket (ws) - 推荐
   - gRPC - 高性能

### 第四步：连接

1. 点击"连接"按钮
2. 观察状态指示器变化：
   - 🟠 橙色 = 正在连接
   - 🟢 绿色 = 已连接
   - 🔴 红色 = 连接错误
3. 查看日志窗口了解详细信息

### 第五步：使用代理

连接成功后，配置你的应用程序使用代理：

#### 浏览器配置
```
代理类型: SOCKS5 或 HTTP
代理地址: 127.0.0.1
代理端口: 30000
```

#### 系统代理（自动）
勾选"自动设置系统代理"选项，程序会自动配置系统代理。

#### 命令行工具
```bash
# 使用 curl
curl -x socks5://127.0.0.1:30000 https://example.com

# 使用 wget
wget -e use_proxy=yes -e http_proxy=127.0.0.1:30000 https://example.com
```

## 常见场景

### 场景 1: 基本 WebSocket 连接

```
服务器地址: your-worker.workers.dev:443
身份令牌: your-uuid-token
监听地址: 127.0.0.1:30000
传输模式: WebSocket (ws)
```

点击"连接" → 等待绿色状态 → 开始使用

### 场景 2: gRPC 高性能模式

```
服务器地址: grpc://your-server:50051
身份令牌: your-uuid-token
监听地址: 127.0.0.1:30000
传输模式: gRPC
并发连接数: 2
```

点击"连接" → 等待绿色状态 → 开始使用

### 场景 3: TUN 全局代理（需要管理员权限）

1. 以管理员身份运行程序
2. 配置基本信息
3. 点击"显示高级设置"
4. 勾选"启用 TUN 模式"
5. 点击"连接"

**注意**: TUN 模式会捕获所有网络流量，无需配置应用程序代理。

### 场景 4: 禁用 ECH（兼容模式）

如果连接失败，可以尝试禁用 ECH：

1. 点击"显示高级设置"
2. 勾选"禁用 ECH (Fallback 模式)"
3. 重新连接

## 故障排查

### 问题 1: 找不到 ech-core.exe

**症状**: 启动时提示找不到可执行文件

**解决方案**:
1. 确保 ech-core.exe 在程序目录中
2. 重新构建项目
3. 手动复制 ech-core.exe 到程序目录

### 问题 2: 连接失败

**症状**: 状态显示红色，日志显示错误

**解决方案**:
1. 检查服务器地址是否正确
2. 验证身份令牌是否有效
3. 尝试禁用 ECH
4. 检查网络连接
5. 查看详细日志信息

### 问题 3: TUN 模式启动失败

**症状**: 提示需要管理员权限或启动失败

**解决方案**:
1. 以管理员身份运行程序
2. 确保 wintun.dll 存在
3. 检查系统是否支持 TUN
4. 查看日志中的错误信息

### 问题 4: 日志不显示

**症状**: 日志窗口空白

**解决方案**:
1. 检查进程是否正常启动
2. 查看任务管理器中是否有 ech-core.exe
3. 尝试重启程序
4. 检查是否有权限问题

### 问题 5: 代理不工作

**症状**: 连接成功但无法访问网站

**解决方案**:
1. 确认应用程序代理配置正确
2. 检查监听地址是否正确
3. 尝试使用 curl 测试代理
4. 查看日志中是否有错误

## 高级技巧

### 技巧 1: 提高并发性能

增加并发连接数可以提高性能：
```
并发连接数: 2-5
```

### 技巧 2: 使用 IP 直连

绕过 DNS 解析，提高连接速度：
```
服务器 IP: 1.2.3.4
```

### 技巧 3: 自定义 DNS

使用更快的 DoH 服务器：
```
DNS 服务器: dns.google/dns-query
```

### 技巧 4: 日志管理

- 定期清除日志保持界面清爽
- 日志会自动限制在 500 条
- 可以复制日志内容用于问题排查

## 性能优化

### 优化 1: 选择合适的传输模式

- **WebSocket**: 兼容性好，适合大多数场景
- **gRPC**: 性能更好，适合高并发场景

### 优化 2: 调整并发连接数

- 低延迟网络: 1-2 个连接
- 高延迟网络: 3-5 个连接
- 不建议超过 10 个

### 优化 3: 使用 TUN 模式

TUN 模式性能最好，但需要管理员权限：
- 无需配置应用程序代理
- 自动捕获所有流量
- 适合全局代理场景

## 安全建议

1. **保护身份令牌**: 不要分享你的 UUID/Token
2. **使用 ECH**: 启用 ECH 提高隐私保护
3. **定期更新**: 保持程序和依赖更新
4. **检查日志**: 定期查看日志发现异常
